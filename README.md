# Практическая работа №4 Перекличка у водосборника
1. **Что хранит элемент `List<Hero>`?**
   Элемент списка хранит ссылку на существующий в памяти объект `Hero`, а не его копию.

2. **Почему созданный через `new Hero(...)` объект ещё не в списке?**
   Создание объекта и добавление его в коллекцию — два отдельных действия: объект существует сам по себе, пока его явно не передадут в метод `Add()`.

3. **Чем `Count` отличается от последнего индекса?**
   `Count` показывает общее количество элементов в списке, а нумерация индексов начинается с `0`, поэтому последний индекс всегда равен `Count - 1`.

4. **Что обозначает `hero` в `foreach (Hero hero in guild.Heroes)`?**
   Это локальная переменная цикла, которая на каждом шаге по очереди получает ссылку на текущий элемент списка.

5. **Почему урон через переменную виден и через список?**
   Переменная и элемент списка ссылаются на один и тот же объект в памяти, поэтому изменение его состояния видно отовсюду.

6. **Что `private set` у `Heroes` запрещает, а что пока разрешает?**
   `private set` запрещает перезаписать само свойство новым списком извне (`guild.Heroes = new List<Hero>()`), но разрешает получать существующий список через `get` и менять его содержимое (например, добавлять дубликаты через `Add`).

**Трассировка:**
* Таблица ссылок: индекс `0` — `first` (Health: `70`), индекс `1` — `second` (Health: `80`), индекс `2` — `first` (Health: `70`).
* Мой прогноз: `3`, `70`, `Первый: 70`, `Второй: 80`, `Первый: 70`, `Второй`. Фактический вывод полностью совпал с прогнозом, ошибок при трассировке не было; в фрагменте создано два объекта `Hero`.

**Ошибка 1:** причина — обращение по индексу `guild.Heroes.Count` выходит за границы списка (при 5 элементах максимальный индекс равен `4`), а проверка `Count > 0` защищает только от пустого списка; исправление — `guild.Heroes[guild.Heroes.Count - 1]`.

**Ошибка 2:** причина — вызов `new Hero(...)` внутри `Add` создал независимую копию объекта, поэтому урон оригинала на неё не повлиял; исправление — `probeList.Add(probeHero);`.

**Самостоятельный шаг:**
* Подсчёт героев со здоровьем от 120 дал `2` (Артём и Александр), самый здоровый — `Александр (150)`.
* Начальным значением берётся `guild.Heroes[0]`, чтобы сравнивать героев с реально существующим участником списка, а не с вымышленным объектом с нулевым здоровьем.
* При одинаковом максимальном здоровье в `strongest` останется **первый** из них, так как используется строгое сравнение `hero.Health > strongest.Health` и следующий герой с тем же здоровьем не перезапишет переменную.

### Личный проект
* **Условие подсчёта и почему:** подсчёт товаров с остатком на складе меньше 3 штук (`StockQuantity < 3`). Это имеет смысл для моей темы, так как помогает вовремя выявить дефицитные товары, которые пора дозаказать на склад.
* **Какой объект изменил и как проверил ссылку:** после добавления в список у объекта `shield` («Железный щит») был вызван метод `shield.Sell(4)`, уменьшивший остаток с `10` до `6`. Проверка через `warehouse.Products[0].StockQuantity` также показала `6`, что подтвердило хранение ссылки в списке.
* **Аналог `Guild`:** да, создан класс `Warehouse` (склад), потому что он объединяет название склада (`Name`) и состав его товаров (`Products`), что логично для предметной области торговли.

### Дополнительная часть
* **Д.1 (Пустая гильдия и две гильдии):** тело цикла `foreach` по пустой гильдии не выполнилось ни разу, так как количество элементов `Count` равно `0`. У двух гильдий разные списки, потому что свойство `Heroes` инициализируется выражением `= new List<Hero>()` отдельно для каждого создаваемого экземпляра `Guild`, даже если внутри обоих списков хранится ссылка на одного и того же героя.
* **Д.2 (Здоровее среднего):** без проверки `Count > 0` при делении на `guild.Heroes.Count` в пустой гильдии произойдёт деление на ноль, что приведёт к аварийному завершению программы с ошибкой `DivideByZeroException`.
